# 必見スケジュール ops スキル

必見パチ/スロの `image_mappings.yaml` を編集し、サブカテゴリの追加・変更・画像差し替えを行う。

## 対応する作業タイプ

### 1. ▼サブカテ追加
新しいサブカテゴリを `image_mappings.yaml` に追加する。

- 管理No（イベント管理番号）を特定する
- 画像ファイルを `{管理No}_{連番}.jpg` にリネームして配置
- `image_mappings.yaml` に新規エントリを追加
- 重複チェック: 同名エントリが既にある場合はスキップして報告

### 2. ▼画像変更（差し替え）
既存サブカテゴリの画像ファイルを新しいものに差し替える。

**重要**: 「差し替え」「変更」「修正」「更新」は既存エントリの上書きを意味する。
- 対象のサブカテゴリが `image_mappings.yaml` に既に存在することを確認
- 添付された新しい画像ファイルを `{管理No}_{連番}.jpg` にリネーム
- **既存エントリの画像パスを新しいファイルに更新する**（エントリが存在するから「対応不要」ではない）
- 古い画像ファイルは削除 or 上書き

### 3. ▼クローズ対応
サブカテゴリを無効化する（close フラグ設定）。

## 作業手順

1. メッセージから作業タイプ（追加 / 差し替え / クローズ）を判定
2. 管理No とサブカテゴリ名を特定
3. `image_mappings.yaml` の現在の状態を確認
4. 必要な編集を実施
5. 添付画像がある場合はリネームして配置
6. 変更を commit & push

## 判定ルール

- 「追加」「新企画」 → 新規エントリ追加
- 「差し替え」「変更」「修正」「更新」「このものに」 → **既存エントリの画像更新**（対応不要ではない）
- 「クローズ」「終了」「停止」 → クローズ処理
- 障害報告・確認依頼・雑談 → スコープ外（`OPS_RESULT: no_action`）

## 注意事項

- 既存エントリのフォーマットに合わせること
- `image_mappings.yaml` の編集時は既存エントリの順序を崩さないこと
- スレッドの会話履歴がある場合、前のメッセージの文脈を必ず考慮すること
